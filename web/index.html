How to read the city

Your codebase is a metropolis. Districts are bounded contexts, buildings are modules (taller = more code), and every car is one dependency driving to the module it uses. Roads exist only where your architecture rules allow a dependency — anything else has to bulldoze a dirt road through the woods. Cranes and scaffolding are uncommitted work; a commit is the grand opening.

🏙Downtown = your core tier; ring roads = the boundaries between tiers
🛣Highways = allowed dependencies between districts
🟫Dirt road through the forest = a rule break between districts
🥾Trampled path across a lawn = a rule break inside a district
🟥Red roof / red car = a module or dependency that breaks a rule
🏗Crane = new file · scaffolding = edited file · rubble = deleted file
🚧Bulldozer + inspector = an uncommitted rule break (fix it before you commit)
🏭Smokestacks = a run-down district (grade C or worse)
🦨Stained walls + green stink lines = a smelly file (very long, long or complex functions, deep nesting)
🌡Lenses recolour every building by size, complexity, function length, churn, freshness, load or bus factor
🚁The news chopper flies to whatever is happening — press U to ride along
🚓Police pulling a red car over = a rule break — click the cruiser for the ticket
🌧Weather follows health: the sky tracks the city rating, rain clouds park over grade D districts, storms over F
🧭Selected lanes: blue = it depends on, teal = depends on it, red = breaks a rule
